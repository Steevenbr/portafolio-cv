Ingeniero de Software

Steeven Bryan Flores Vega

Soy Ingeniero de Software graduado de la Universidad de las Fuerzas Armadas ESPE, especializado en el diseño y construcción de sistemas tecnológicos robustos, escalables y orientados a la calidad. Mi filosofía de desarrollo se fundamenta en la rigurosidad analítica y la aplicación de Clean Architecture junto con Domain-Driven Design (DDD), estructurando soluciones donde la lógica de negocio central es totalmente independiente de frameworks o infraestructuras externas.

Cuento con una visión integral del ciclo de vida del software: desde el modelado de microservicios backend y la integración de APIs corporativas para comercio electrónico, hasta la orquestación de entornos de desarrollo y la programación de lógicas de decisión avanzadas (FSM, Behavior Trees) para simuladores. Mi objetivo como profesional es transformar requerimientos complejos en arquitecturas eficientes, garantizando siempre alta cohesión, bajo acoplamiento y código preparado para evolucionar en producción.

Filosofía de Desarrollo y Arquitectura

Mi enfoque no es solo escribir código que funcione, sino diseñar sistemas mantenibles, escalables y testeables a largo plazo.

Clean & Arquitectura Hexagonal

Estructuro mis aplicaciones separando estrictamente el núcleo del negocio de los detalles técnicos. Utilizo Arquitectura Hexagonal (Puertos y Adaptadores) y Clean Architecture junto con DDD para crear sistemas robustos, altamente testeables e independientes de frameworks, bases de datos o interfaces externas.

Control de Versiones y Entornos

Gestiono el código fuente de manera estructurada con Git y preparo entornos de desarrollo utilizando contenedores (Docker) y WSL. Esto me permite asegurar que el software y la arquitectura diseñada funcionen de manera consistente en cualquier máquina.

Patrones de Diseño y SOLID

Aplico principios SOLID y patrones de diseño orientados a objetos (OOP). En mis proyectos (desde apps web hasta IA para videojuegos con Máquinas de Estado) priorizo la alta cohesión y el bajo acoplamiento para facilitar futuras actualizaciones.

Modelado y Documentación UML

Antes de escribir la primera línea de código, modelo la solución. Construyo diagramas de clases, flujos BPMN, diagramas de casos de uso y de componentes (draw.io, Lucidchart) para tener un mapa claro de la arquitectura y facilitar el trabajo en equipo.
